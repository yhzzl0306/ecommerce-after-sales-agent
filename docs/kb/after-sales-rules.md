# 电商售后规则知识库（第一版）

> 项目：电商售后智能体
> 日期：2026-09-27
> 用途：导入 Dify 知识库，用于售后资格判断和人工转派。
> 声明：以下规则是项目演示用的脱敏示例，不代表真实平台政策。

## 1. 未发货订单退款

### 适用条件

- 订单状态为已支付，但尚未发货；
- 当前没有已经完成或处理中的售后申请；
- 用户明确提出退款或取消订单。

### 处理规则

- 优先查询订单状态和支付状态；
- 未发货订单可以进入退款申请判断；
- 如果订单已进入出库或发货流程，不直接承诺退款成功；
- 需要结合实际支付渠道和履约状态转人工或进入审核。

### 需要验证的数据

- 订单状态；
- 支付状态；
- 发货状态；
- 当前售后申请状态。

## 2. 已签收 7 天内的质量问题

### 适用条件

- 订单已完成或已签收；
- 签收时间距当前不超过 7 个自然日；
- 用户描述为质量问题、功能故障或商品损坏；
- 商品不属于明确排除的特殊品类。

### 处理规则

- 先查询物流签收时间；
- 再查询商品类型和订单售后状态；
- 符合基础条件时，可以创建售后申请并进入人工审核；
- 不应直接承诺退款已经完成，工具只能创建申请。

### 需要验证的数据

- 签收时间；
- 当前时间；
- 商品类型；
- 售后申请状态；
- 订单金额。

## 3. 已签收超过 7 天

### 处理规则

- 不直接判断为可以退款；
- 需要根据商品类别、质量凭证和平台特殊政策继续判断；
- 信息不足时转人工；
- LLM 必须明确说明“超过示例规则时限，需要人工审核”，不能编造例外政策。

## 4. 特殊商品

以下商品暂按特殊商品处理：

- 定制商品；
- 生鲜食品；
- 虚拟商品；
- 已拆封且影响二次销售的商品；
- 其他需要人工确认的特殊品类。

### 处理规则

- 即使订单已签收，也不能仅凭普通商品规则自动判断；
- 需要提示用户准备质量凭证或商品照片；
- 默认转人工审核；
- 创建售后前必须获得用户明确确认。

## 5. 已存在处理中售后申请

### 处理规则

- 如果订单已经存在 `PENDING_REVIEW`、`APPROVED` 或 `REFUNDING` 状态的售后申请，不允许再次创建相同订单的处理中申请；
- 应向用户返回当前售后申请状态；
- 如果用户认为信息错误，转人工处理；
- 服务端必须通过幂等键和业务状态校验防止重复创建。

## 6. Agent 输出要求

Agent 必须区分以下信息来源：

| 信息 | 来源 |
|---|---|
| 订单号、金额、订单状态 | 订单查询工具 |
| 签收时间、物流状态 | 物流查询工具 |
| 退款时限、特殊商品规则 | 售后规则知识库 |
| 是否创建售后 | 用户明确确认 + 售后工具返回 |

当规则或业务数据不足时，必须输出：

```text
当前信息不足，无法直接判断是否符合售后条件，建议补充信息或转人工审核。
```

不得编造：

- 订单状态；
- 支付金额；
- 签收时间；
- 平台不存在的售后政策；
- 已经完成的退款结果。
