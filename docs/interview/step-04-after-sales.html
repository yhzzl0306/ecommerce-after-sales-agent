4. 面试八股：三层防线

Prompt 层约束模型，工作流条件层约束调用路径，FastAPI 服务端层校验最终业务不变量。创建售后申请有副作用，不能只依赖 Prompt。

5. 幂等设计

服务端维护 idempotency_key → application 映射。首次请求创建申请；相同幂等键重试时返回原申请并带 X-Idempotent-Replay: true；同一幂等键绑定其他订单或类型时返回 409。生产环境应使用数据库唯一索引或 Redis，并处理并发、过期和多实例一致性。

10. 2026-10-09：重复申请查询分支联调成功

HTTP 节点的 body 包含 has_active_application: true，但 Dify 条件分支不会自动展开 JSON 内部字段。新增代码节点“解析处理中申请结果”，将 body 解析后输出布尔变量，并将条件设置为：

解析处理中申请结果 / has_active_application == true

订单 202609070001 测试进入 IF 分支，创建售后申请节点未执行。最终申请号为 ASA199F40A7B8B，状态为 PENDING_REVIEW。

面试要点：工作流节点之间需要明确数据契约；字符串 "true" 与布尔值 true 不能混用。
